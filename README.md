# FlukeEventView

**Открытая Windows-реализация программы EventView V2.16 для регистратора качества электроэнергии Fluke VR101 / VR101S (OEM ACR PowerWatch).**

> An open-source re-implementation of the Fluke EventView V2.16 companion software for the
> Fluke VR101 Voltage Event Recorder. Written in C# / WinForms (.NET Framework 4.7.2).
> Works over the original optical Lite-Link adapter (RS-232, 9600-N-8-1).

Оригинальный `EV101.EXE` — 16-битное приложение Visual Basic 3.0 (NE, p-код) 1997–2001 годов.
На современных 64-битных версиях Windows оно запускается только через эмуляцию Win16 и работает
нестабильно. Этот проект повторяет функциональность оригинала на актуальной платформе и
добавляет то, чего в оригинале не было.

---

## Возможности

### Работа с прибором
- Подключение к регистратору через оптический адаптер **Lite-Link** (питание адаптера по линиям DTR/RTS).
- Фоновый опрос состояния (пакет `00 FF FF 41 BE`) с обновлением **только динамических** показаний:
  напряжение фаза–нейтраль, нейтраль–земля, частота сети, наработка.
- Чтение уставок из прибора (пороги всплесков/просадок, импульсов, частоты, режим буфера, описание объекта).
- Выгрузка журнала событий блоками по 256 байт (32 события) с проверкой контрольной суммы.
- Запись уставок и очистка памяти прибора одним действием (как «Send Setup / Clear Recorder» в оригинале).
- Индикаторы **ONLINE / TX / RX** в строке состояния: видно, что программа реально обменивается данными с прибором.
- Протокольный лог в HEX — для диагностики связи.
- Окно **VR101 Calibration**: показывает текущее измерение прибора, принимает показание внешнего
  вольтметра и рассчитывает поправочный коэффициент (запись в прибор не выполняется — см. «Ограничения»).

### События и анализ
- Декодирование 8-байтовых записей: тип, амплитуда, длительность (полупериоды / секунды / минуты), фаза импульса в градусах, метка времени.
- Классы событий: H-N Swell, H-N Sag, H-N Transient (±Vp), N-G Swell, N-G Transient, High/Low Frequency, Outage, Open Event.
- Таблица событий с фильтрацией **по типу** и **по интервалу даты/времени** (фильтр учитывается в графиках и экспорте).
- **Сводные счётчики** над таблицей: всего событий, всплески, просадки, импульсы, обрывы, события частоты; при переполнении памяти — отметка `ПАМЯТЬ ЗАПОЛНЕНА`.
- Пометка **«(не сохранено)»**: данные считаны из прибора, но ещё не сохранены в файл.
- **Graph Setup** как в оригинале: тумблеры показа событий H-N / N-G и число периодов для гистограммы.
- **Печать отчёта** (`Ctrl+P`) с предварительным просмотром: шапка с серийным номером, прошивкой, режимом, порогами и сводкой, затем таблица событий с постраничной разбивкой.
- **Профили порогов** — 12 наборов в один клик: 5 арбитражных по нормативным документам (ГОСТ 32144-2013, EN 50160, ANSI C84.1 Range A, IEC 61000-2-4) и 7 практических сценариев (чувствительная нагрузка, ЦОД, промышленный объект, ИБП, диагностика сети, только тяжёлые отклонения, базовый), см. [docs/PRESETS.md](docs/PRESETS.md).
- Учёт **минимума и максимума** напряжения и частоты за сессию подключения (с кнопкой сброса) — удобно для оценки близости к порогам.
- Три режима графиков:
  1. гистограмма событий по периодам (*Quick Summary*);
  2. распределение «амплитуда — длительность» (*Event Distribution*);
  3. осциллограмма одиночного импульса на синусоиде сети (*Single Transient*) с фазовым углом.
- Сохранение любого графика в PNG / BMP / JPG.

### Файлы
- Открытие и сохранение файлов сессии **`.VER`** (формат EventView V2.x: 152-байтный заголовок + записи по 16 байт).
- Экспорт событий в CSV.
- Совместимость чтения: файлы, созданные оригинальной программой, читаются без конвертации.

### Интерфейс
- Двуязычный интерфейс: **русский / английский**, переключение на лету.
- Масштабирование шрифта: кнопки `A- / A+ / 100%`, `Ctrl + колесо мыши`, `Ctrl +/-/0`.
- Вкладки `Status | Events | Graphs | Protocol Log`.

## Профили порогов

На вкладке **«Статус»** есть панель «Профиль порогов»: выберите набор и нажмите
**«Применить профиль»** — значения подставятся в поля Sag / Swell / Min / Max частоты.
Запись в прибор — отдельной кнопкой «Записать уставки / Очистить память прибора».

Профили делятся на **арбитражные** (★, значения из нормативных документов — для сопоставления
результатов с требованиями) и **сценарии** (инженерные наборы под тип объекта). Ни те, ни
другие не меняют пороги импульсов и N-G: единого норматива для них нет.

### Арбитражные профили

| Профиль | Sag | Swell | Частота | Основание |
|---|---|---|---|---|
| ★ ГОСТ 32144-2013: ±10 % / ±0,2 Гц | 198 В | 242 В | 49.8 … 50.2 Гц | 220 В ±10 %; частота ±0,2 Гц для 95 % времени недели |
| ★ ГОСТ 32144-2013: ±10 % / ±0,4 Гц | 198 В | 242 В | 49.6 … 50.4 Гц | частота ±0,4 Гц — предел для 100 % времени |
| ★ EN 50160: ±10 % / ±1 % | 198 В | 242 В | 49.5 … 50.5 Гц | ±10 % для 95 % времени недели; частота ±1 % для 99,5 % года |
| ★ ANSI C84.1 Range A: ±5 % | 210 В | 230 В | 49.5 … 50.5 Гц | Range A: 114…126 В на 120 В; частота — по EN 50160 |
| ★ IEC 61000-2-4, класс 2: ±10 % | 198 В | 242 В | 49.5 … 50.5 Гц | ±10 % от номинала; частота ±1 % |

### Профили-сценарии

| Профиль | Sag | Swell | Частота | Когда применять |
|---|---|---|---|---|
| Чувствительная нагрузка (±7,5 %) | 204 В | 236 В | 49.8 … 50.2 Гц | серверные, лабораторное и медицинское оборудование |
| Серверная / ЦОД: глубокие провалы | 187 В | 242 В | 49.5 … 50.5 Гц | провалы до −15 %, после которых ИТ-оборудование перезагружается |
| Промышленный объект с двигателями | 176 В | 253 В | 49.6 … 50.4 Гц | пуски двигателей — норма, важны длительные отклонения |
| ИБП / резервное питание | 176 В | 242 В | 49.5 … 50.5 Гц | проверка перехода на резервный источник |
| Диагностика сети (±2 %) | 216 В | 224 В | 49.9 … 50.1 Гц | обследование: максимальная чувствительность, много событий |
| Только тяжёлые отклонения (±20 %) | 176 В | 264 В | 49.0 … 51.0 Гц | минимум ложных срабатываний |
| Базовый — заводские | 210 В | 256 В | 48.8 … 51.2 Гц | значения по умолчанию программы |

Значения приведены к шагам прибора (2 В для H-N, 0,1 Гц для частоты), поэтому «идеальные» ±5 %
(209…231 В) записываются как 210/230 В — в сторону более строгого контроля. Подробности,
ограничения и ссылки на документы: [docs/PRESETS.md](docs/PRESETS.md).

## Требования

| | |
|---|---|
| ОС | Windows 7 / 10 / 11 (x64) |
| Среда | Visual Studio 2019 (или MSBuild 16+), .NET Framework **4.7.2** |
| Порты | Физический или USB-RS232 COM-порт |
| Оборудование | Fluke VR101 / VR101S + оптический адаптер Lite-Link |

> Для питания оптического адаптера программа принудительно поднимает линии **DTR** и **RTS** —
> без этого «глазок» Lite-Link не работает. Учтите это, если используете USB-переходник:
> не все дешёвые переходники обеспечивают достаточный ток по этим линиям.

## Сборка

```bash
git clone <repo-url>
cd FlukeEventView
```

Откройте `FlukeEventView.sln` в Visual Studio 2019 и нажмите **F5**, либо соберите из консоли:

```powershell
& "C:\Program Files (x86)\Microsoft Visual Studio\2019\Community\MSBuild\Current\Bin\MSBuild.exe" `
  .\FlukeEventView.csproj /t:Rebuild /p:Configuration=Release
```

Готовый файл: `bin\Release\FlukeEventView.exe` (зависимостей кроме .NET Framework нет).

## Быстрый старт

1. Подключите оптический адаптер Lite-Link к COM-порту ПК.
2. Запустите программу и выберите порт в выпадающем списке на панели инструментов.
3. Нажмите **«Старт опроса»** (`Start Scanning`).
4. Вставьте «глазок» адаптера в окно ИК-порта регистратора. Индикатор **VR101** станет зелёным,
   в блоке *RealTime* появятся напряжение и частота.
5. Нажмите **«Загрузить события»** — журнал будет выгружен и показан на вкладке `Events`.

> **Важно.** Пока идёт сеанс связи, регистратор не пишет в память. Чтобы прибор снова начал
> автономный мониторинг, нажмите «Стоп опроса» и выньте «глазок» из прибора.

### Запись уставок и очистка памяти

Кнопка **«Записать уставки / Очистить»** (`Send Setup / Clear Recorder`) записывает текущие
пороги с левой панели и **одновременно очищает журнал прибора** — как в оригинальном EventView.
Перед выполнением программа спрашивает подтверждение. Рекомендуется предварительно сохранить
файл `.VER`.

Пороги вводятся с контролем аппаратных ограничений прибора: при вводе значения, не кратного шагу
(2 В для порогов H-N в режиме 220 В, 10 В для импульсов), оно автоматически округляется до
ближайшего допустимого, а диапазон зажимается в пределах, которые принимает регистратор.

## Файлы сессии `.VER`

Формат описан в разделе [docs/VER-format.md](docs/VER-format.md) (при наличии файла).
Кратко: сигнатура `.2`, 152-байтный заголовок (время начала/окончания, серийный номер, версия
прошивки, уставки, описание объекта, указатель буфера, три слота незавершённых событий) и
массив событий по 16 байт. Число событий надёжно определяется по длине файла: старые файлы
могут содержать недостоверный счётчик в заголовке.

## Протокол обмена (кратко)

- `9600`, 8 данных, без чётности, 1 стоп-бит; **DTR = RTS = ON**.
- Префикс пробуждения `00 FF FF`, далее байт команды и контрольный байт `0xFF - (Σ байтов команды)`.
- `... 41 BE` — запрос 88-байтного заголовка состояния.
- `... 42 <n> <crc>` — чтение блока событий `n` (256 байт данных).
- `... 58 <параметры...> <crc>` — запись уставок (прибор отвечает `'Y'`).
- Оптический адаптер возвращает **эхо** отправленной команды, поэтому парсер пропускает эхо
  и читает полезную нагрузку по длине.

Технические подробности и результаты реверс-инжиниринга: [docs/PROTOCOL.md](docs/PROTOCOL.md).

## Ограничения

- Поддержка **модемного** подключения (PhoneBook, Modem Setup) оригинала не реализована:
  PowerWatch/VR101 её фактически не поддерживает.
- **Запись калибровочного коэффициента в прибор** не выполняется: формат хранения калибровки
  VR101 не подтверждён, а ошибочная запись изменила бы показания прибора. Окно калибровки
  считает отклонение и коэффициент, результат пишется только в протокол программы.
- **Loss of Synchronization** отображается как отдельная категория, но формируется **программой**,
  а не прибором: если при опросе счётчик наработки регистратора уменьшается, в таблицу событий
  добавляется помеченная запись «Потеря синхронизации» (жёлтый фон, курсив), она же учитывается
  в сводке и доступна в фильтре. Код события в протоколе для этого сообщения пока не установлен —
  см. `tools/make_codesweep_ver.py`. Такие записи не сохраняются в `.VER`.
- Неизвестные/редкие коды событий отображаются как `Событие 0x??` — такие записи можно
  прислать в issue вместе с HEX-дампом, чтобы уточнить декодирование.

## Тестовые данные

`tools/make_codesweep_ver.py` собирает файл `.VER` с одной записью на каждый возможный код
события `B1` (0x00…0xFF). Если открыть такой файл в оригинальном EventView и выгрузить список,
получается эталонная таблица «код → как событие называет оригинал». Она нужна, чтобы закрыть
неизвестные коды, включая «Loss of Synchronization».

```bash
python tools/make_codesweep_ver.py CODESWEEP.VER
```

проприетарные материалы Fluke: для работы нужен собственный прибор и адаптер.
