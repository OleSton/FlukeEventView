# Формат файлов сессии `.VER` (EventView V2.x)

Формат используется оригинальной программой EventView для сохранения считанных данных.
Файлы, созданные оригиналом, читаются нашей реализацией без конвертации, и наоборот.

## 1. Общая структура

```
+0x00  сигнатура ".2" (2 байта; старые файлы имели ".1")
+0x02  заголовок, 150 байт
+0x98  массив событий: N записей по 16 байт
```

Итого смещение массива событий — `152` (`0x98`).

## 2. Заголовок (150 байт, смещения от `+0x02`)

| Смещение в файле | Размер | Содержимое |
|---|---|---|
| 0x02 | 8 | время окончания записи, `double` в формате OLE Automation Date |
| 0x0A | 8 | время начала записи, `double` OLE Automation Date |
| 0x12 | 4 | счётчик наработки в тиках по 8 с (`int32`) |
| 0x16 | 4 | серийный номер прибора (`int32`, `0x6D8D` = 28045) |
| 0x1A | 2 | живое напряжение H-N, сырое значение (`int16`) |
| 0x1C | 2 | живое напряжение N-G, сырое значение |
| 0x20 | 2 | байт опций (50 Гц / FIFO / мигание) |
| 0x22 | 4 | слово верхнего порога частоты (`int32`), Гц = `57600 / word` |
| 0x26 | 4 | слово нижнего порога частоты |
| 0x2A | 2 | порог просадки H-N, сырое значение (×2 В для 220 В) |
| 0x2C | 2 | порог всплеска H-N |
| 0x2E | 2 | порог импульса H-N (×10 В) |
| 0x30 | 2 | порог превышения N-G |
| 0x32 | 2 | порог импульса N-G (×10 В) |
| 0x34 | 30 | описание объекта, ASCII, дополнено пробелами |
| 0x52 | 2 | мёртвая зона (`FixedDeadBand`) |
| 0x54 | 4 | размер буфера (32000) |
| 0x58 | 4 | лимит (`Limit`) |
| 0x5C | 2 | байт конфигурации (`0x80` — 220 В, `0x10` — N-G 0.25 В, младшие 4 бита — прошивка) |
| 0x66 | 8 | живая частота (`double`, Гц) |
| 0x6E / 0x72 | 4 / 4 | счётчики буфера в байтах (`int32`) — **могут быть недостоверны**, см. п. 4 |
| 0x7E | 24 | три слота незавершённых событий (`Open Event`) по 8 байт |
| 0x96 | 2 | флаг наличия выгруженных событий (не количество!) |

## 3. Записи событий

Каждая запись занимает **16 байт** и представляет собой 8 значений `UInt16` (little-endian),
в которых значим только младший байт. Логическая запись — те же 8 байт, что прибор отдаёт по
протоколу (см. `docs/PROTOCOL.md`, раздел 5).

```
offset 152 + 16*i :  b0 00  b1 00  b2 00 ... b7 00
```

## 4. Количество событий

Надёжный способ — по длине файла:

```
count = (fileLength - 152) / 16
```

Поля-счётчики в заголовке (`0x6E`, `0x72`) в старых файлах не соответствуют реальному числу
записей. Проверено на поставлявшемся с программой `SAMPLE.VER`: файл содержит **194** записи,
а поле заголовка даёт `544 / 8 = 68`. Поэтому наша реализация определяет количество по длине
файла.

## 5. Совместимость

* Чтение: поддерживаются файлы `.1` (устаревший) и `.2`;
* запись: формат `.2`;
* время в заголовке — OLE Automation Date (дни от 1899-12-30), поэтому файл корректно
  открывается в том числе сторонними средствами.

## 6. Ограничения

* Файл хранит только уже считанные данные; обрыв питания прибора и его собственные счётчики
  в файле не отражаются;
* описания неизвестных кодов событий не сохраняются — хранится только сырая запись.
